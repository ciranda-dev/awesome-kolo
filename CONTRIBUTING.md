# Contributing

This is a curated list. A good entry is something you built or used with Kolo, or something that helps others do the same.

## Add an entry

1. Open a pull request that changes `README.md` only.
2. Put the entry in the section it belongs to, in the table format used there: name as a link, then one plain sentence about what it does.
3. The entry must be about Kolo: built on its libraries, or about them. Say what it uses.
4. The project must work today. Mark anything unfinished as beta in its own README.
5. One entry per pull request, so each can be reviewed alone.

## What does not go in

- Anything that presents itself as made or endorsed by Ciranda when it is not.
- Projects that do not work, cannot be built from their own instructions, or have no public page to look at.
- Projects that are only advertising: the entry must say what the software does and what it uses.
- Anything that asks people for keys, secrets, payments or personal data.

## Keep it plain

- English, short sentences, no marketing words.
- No claims you cannot show. If you give a number, say how you measured it.
- Check the link opens.

## Report a problem in a library

Problems in a library go to that library's repository, not here. For a security problem, use the repository's private report (SECURITY.md in each repository).
